## Remaining blockers (external — need the owner)

1. **npm publication** — `@drift/ast` / `@drift/core` / `@drift/cli` /
   `@drift/mcp` are unpublished (registry 404). Owner action:
   `npm adduser` (or token in `~/.npmrc`), then
   `bash scripts/publish-npm.sh` — full checklist in
   [docs/NPM_RELEASE.md](NPM_RELEASE.md). After publishing, move the npx
   commands back to first position in README + manifests and record the live
   npx measurement.
2. **GitHub Actions must be enabled** on the account for CI to run
   (Settings → Actions → General → *Allow all actions*). Until then CI has no
   public runs — the same commands are verified green locally.
3. **Issues must be enabled** for the new issue templates to appear
   (Settings → General → Features → Issues). Private vulnerability reporting
   is referenced by SECURITY.md and the issue config.

## Known limitations (accepted, documented)

- Files untracked by ADR-009's `git rm --cached` remain in old commits' git
  history — repositories that committed prompts before this change must treat
  that history as exposed and rotate affected secrets (`drift doctor` warns).
- The demo repo's embedded git history cannot be committed inside the
  repository — a fresh clone must run `bash scripts/seed-demo.sh` first
  (documented in `examples/demo-repo/README.md`).
- `drift verify` re-runs the recorded command with the user's shell — only
  run it on intents you trust (documented in SECURITY.md and api.md).
- Redaction is regex-based defense-in-depth, not a guarantee.
- Encryption at rest protects `.drift` storage; the git commit subject carries
  a summary (default) or the full prompt (only in `[prompts] mode = "full"`).
- `--limit` values and other numeric flags are clamped, never thrown into SQL
  verbatim.
